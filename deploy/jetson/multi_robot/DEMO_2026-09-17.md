## Threshold rollback

Set `loop_verification.min_inliers` in `fleet.yaml` back to 30, regenerate fleet
parameters, and distribute the worker YAML files to each board. Preserve any
board-local camera overrides. Alternatively, each deployed worker YAML has a
`.before-inlier-trial` backup beside it. Stop and Start all workers to load the
restored threshold and clear constraints from the trial sessions. CBS final-only
visualization can stay enabled independently of the threshold.

## Walking out of Wi-Fi coverage

Wi-Fi autoconnect and ROS reconnection are separate. With today's direct DDS
profile, automatic end-to-end recovery on return is unverified. Local tracking
has no CBS dependency, but continued local ROS communication during interface
loss is not guaranteed by the current network binding. Remote previews and
control are unavailable during the outage. Interrupted CBS cycles may abort;
last completed alignments can remain visible. A returning robot needs discovery,
current-session messages, and verified overlap before a new merge can finish.
Keep configured peer IPs stable. Do not promise offline boot with this profile.

The verified 20-second real Wi-Fi disconnect/reconnect test was performed with
the alternative Zenoh bridge profile, not today's direct DDS setup. See
`OFFLINE_NETWORK.md`. No Wi-Fi outage was induced while saving this demo.
